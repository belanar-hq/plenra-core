# BELANAR TREND-TO-OWNED-OUTCOME SYSTEM V1.0

STATUS: USER-APPROVED FOUNDATION
DATE: 2026-10-03

## PURPOSE
Belanar does not ride trends for reach alone. It converts borrowed attention created by a live trend into owned attention, a real decision interaction, and ultimately a measurable outcome.

CORE LOOP:
TREND ATTENTION
→ DECISION TENSION
→ BELANAR RELEVANCE
→ CURIOSITY GAP
→ CONTINUATION CTA
→ OWNED TREND DESTINATION
→ DECISION INTERACTION
→ OWN-DECISION START
→ VERIFIED OUTCOME
→ LEARNING

The social post is an acquisition surface, not the destination.

## PRIMARY DESIGN PRINCIPLE
Do not ask a trend audience to become interested in Belanar before delivering the value that brought them in.
Preserve the user's original curiosity and continue it on a Belanar-owned surface.

Wrong:
TREND → "Learn about Belanar"

Right:
TREND → "What would you have done?" / "See the decision breakdown" → trend-specific Belanar destination

BRANDING != ROUTING.
A logo creates attribution. A CTA plus a valuable continuation creates movement.

## TREND FIT GATE
A trend is publishable only when all are true:
1. ATTENTION: meaningful current attention exists.
2. DECISION TENSION: the story contains a consequential choice, uncertainty, tradeoff, judgment, or action.
3. BELANAR FIT: Belanar can add decision value, not merely commentary.
4. INFORMATION GAP: the social creative can create a legitimate unanswered question without clickbait or withholding essential safety information.
5. OWNED CONTINUATION: Belanar can create a useful destination that resolves or advances that question.
6. VERIFIABILITY: material factual claims can be supported by credible evidence.
7. SPEED: the package can ship while the attention window remains materially open.

If any required gate fails, do not force the trend into Belanar.

## DESTINATION-FIRST RULE
Before finalizing the social creative, define the owned destination and the exact reason to click.

For each trend:
TREND_ID
→ VERIFIED FACTS
→ DECISION QUESTION
→ DESTINATION PROMISE
→ DESTINATION URL
→ CTA
→ CREATIVE
→ PUBLISH

The creative must not promise information or analysis the destination does not actually deliver.

## OWNED TREND DESTINATION CONTRACT
Example: /plane

Minimum flow:
WHAT HAPPENED?
→ WHAT WAS KNOWN AT THE DECISION MOMENT?
→ WHAT OPTIONS / CONSTRAINTS EXISTED?
→ WHAT WOULD YOU DO?
→ BELANAR DECISION BREAKDOWN
→ TRY BELANAR ON YOUR OWN DECISION

The destination should provide immediate standalone value even if the visitor never becomes a user.

## CREATIVE CONTRACT
The creative should contain:
- recognizable trend hook
- the decision tension
- enough verified context to be trustworthy
- Belanar attribution
- one continuation CTA
- destination path when the platform supports it

The creative should NOT:
- summarize the entire destination and eliminate the reason to continue
- use generic "Learn more about Belanar" as the primary CTA
- optimize for brand impressions while leaving no route to an owned asset
- fabricate urgency, uncertainty, or facts
- force a trend into a Belanar narrative when decision relevance is weak

## CTA RULE
CTA = continuation of the trend curiosity, not a corporate introduction.

Preferred CTA patterns:
- What would you have done?
- See the decision breakdown.
- See what was known when the decision had to be made.
- Test your decision against the same constraints.

## MEASUREMENT FUNNEL
Primary acquisition metric:
POST IMPRESSIONS → OWNED DESTINATION VISITS

Then:
DESTINATION VISITS → DECISION INTERACTION
DECISION INTERACTION → OWN-DECISION START
OWN-DECISION START → VERIFIED OUTCOME

Track at minimum:
trend_id
platform
creative_id
published_at
impressions
engagements
profile_visits
destination_visits
decision_interactions
own_decision_starts
verified_outcomes

Do not call a trend successful based only on views, likes, or shares.

## LEARNING
After each trend:
INPUT → trend + evidence
STATE → attention window + fit + destination readiness
DECISION → publish / reject / wait
ACTION → destination + creative + distribution
OUTCOME → owned traffic + decision interactions + outcomes
VERIFICATION → analytics + event evidence
LEARNING → hook/CTA/destination/platform performance

Use learning to improve the mechanism, not to create a permanent rule from one viral example.

## CURRENT REFERENCE CASE: YANIV HAYUN / FLYDUBAI
The hook is not merely an aviation incident. The distinctive tension is:
HE'S A PLUMBER. NOT A PILOT.
→ unexpected high-stakes decision
→ knowledge acquired outside formal role/training
→ decision under severe time pressure
→ outcome relevance

Candidate continuation:
"What would you have done?"
"See how Belanar breaks down the decision."
Destination candidate: /plane

This reference case illustrates the mechanism. It does not constrain future trends to hero stories, aviation, emergencies, or consumer topics.
