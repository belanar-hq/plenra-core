# Make.com Webhook Contract

Defines how Make.com sends WhatsApp intake data to the local mosquito-poc runtime.

## Endpoint

`POST http://localhost:3000/intake`

## Required JSON Payload Fields

- `source_id` — string, campaign source identifier
- `city` — string, customer city
- `area` — string, customer neighborhood or block
- `messages_count` — number, lead engagement count
- `free_text` — string, optional customer note
- `answers` — object, required intake answers
  - `q1` — string, comma-separated bite location codes
  - `q2` — string, mosquito frequency code
  - `q3` — string, duration code
  - `q4` — string, household report count code
  - `q5` — string, comma-separated yard/water codes

### Intake Answer Codes

- `q1` (bites_location): `1,2,3,4,5`
- `q2` (when it occurs): `1,2,3,4,5`
- `q3` (duration): `1,2,3,4,5`
- `q4` (people bitten): `1,2,3,4`
- `q5` (yard/water): `1,2,3,4,5`

## Example Payload

```json
{
  "source_id": "PT-KIRYAT_ARIE-V1",
  "city": "Petah Tikva",
  "area": "Kiryat Arie",
  "messages_count": 5,
  "free_text": "יתושים בערב בעיקר בחצר",
  "answers": {
    "q1": "1,2,3",
    "q2": "4",
    "q3": "2",
    "q4": "2",
    "q5": "1,4"
  }
}
```

## Expected API Response

Success response is JSON with required fields:

```json
{
  "lead_id": "uuid-1234",
  "lead_score": 90,
  "status": "HIGH_PRIORITY",
  "next_action": "BOOKING_PENDING"
}
```

## Error Handling

### 400 Bad Request
- Returned when required fields are missing
- Response body:

```json
{ "error": "Invalid payload: missing answers" }
```

### 500 Internal Server Error
- Returned on runtime or file write failure
- Response body:

```json
{ "error": "Internal server error" }
```

### Retry Policy
- Retry on 500 only
- Do not retry on 400
- Use exponential backoff for transient failures

## Idempotency Key

- Use a Make.com custom header `X-Idempotency-Key`
- Persist this key in scenario state if supported
- Reject duplicate inbound payloads using the same key
- If idempotency key is absent, still process normally

## lead_id Handling

- `lead_id` is generated by the local runtime
- Make.com should not provide `lead_id` on /intake
- Use returned `lead_id` for downstream routing, logging, and follow-up

## source_id Handling

- `source_id` must be provided by Make.com
- It identifies campaign origin and QR source attribution
- Store it in the lead record and use it for analytics
